# Question Bank 录入性能优化与测试隔离

本轮保留资源 SHA-256 校验、幂等和事务检查，将小图片录入的 P95 从同轮基线 1052 ms 降到 477 ms，平均耗时从 916 ms 降到 381 ms。完整严格回归 190 passed，65.97 秒，无 xfail。持续负载 SLA 仍未验收。

## 测试隔离

测试使用同一 RDS 实例上的独立临时数据库，没有向正式题库录入测试数据。业务库连接仅用于读取版本、CREATE DATABASE、DROP DATABASE 和删除结果核对。随后将应用连接切换为随机 qb_acceptance 数据库，再初始化和写入测试数据。完整 pytest 同样先创建专用库，各测试再隔离 schema。云端探针对 8890 只执行认证后的健康检查。

OSS 测试操作限定到独立 `acceptance/<随机值>/` 前缀。优化前后云端运行与完整回归均已核对临时数据库删除成功，云端两轮对象也均清理。前轮修复验收的环境记录亦已复核，测试数据库独立且已删除。

独立数据库仍与业务库共享实例的 CPU、I/O 和连接容量。本轮云端测量是 C=1 的短时运行；回归含已有并发编辑测试。隔离保护业务表与对象命名空间，不表示独占硬件。没有部署、重启 8890 或调用模型。

## 瓶颈与改动

优化前，热资源每题有 12 次 OSS HEAD 和 12 次 GET。HEAD 合计平均 299 ms，GET 合计平均 523 ms；数据库 SQL 合计约 67 ms，事务锁获取约 3 ms。瓶颈主要是对象存储往返。

1. 复用对象直接 GET 并校验摘要，省去前置 HEAD。只有明确的对象缺失错误才允许上传；超时、权限或摘要错误仍失败，不能因读取失败覆盖原对象。新上传仍读回校验。
2. 图片路径查找已检查存在性，删除其后的重复 HEAD；后续 GET 仍检测对象被删除或替换。
3. 单次校验中的独立图片与证据最多使用 4 个线程并行读取、解码、校验。所有 SQL 留在事务所属线程，错误按输入顺序汇总，所有任务完成后才能结束校验。
4. 证据页路径改用单次批量 SELECT。保留提交前和事务内的重新校验，不启用跨读取字节缓存，不改数据库锁粒度。

## 同轮云端对比

两轮均为 30 个新请求、C=1 顺序闭环，每题 4 张 PNG、总计 4721 字节；首题创建对象，后续复用相同 key。计时包括服务内 OSS/RDS 和图片处理，不包括包生成、模型、人工审核。分位数采用 nearest-rank。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 成功录入 | 30/30 | 30/30 |
| 平均响应耗时 | 916.12 ms | 380.94 ms |
| P50 | 902.73 ms | 373.71 ms |
| P95 | 1052.04 ms | 476.70 ms |
| P99 | 1120.08 ms | 769.57 ms |
| 30 次调用累计耗时 | 27.48 s | 11.43 s |
| 热资源每题 HEAD | 12 | 4 |
| 热资源每题 GET | 12 | 12 |
| 每题普通 SQL execute 次数 | 25 | 23 |

平均耗时下降约 58%，P95 下降约 55%。优化后 GET 累计操作耗时约 550 ms，但多个读取并行，不能将其相加后当作请求墙钟时间。SQL 分类记录客户端 execute 耗时，包含网络往返，不是服务端纯执行时间；锁分类记录获取锁耗时而非持锁时长。

此前修复报告的 P95 1730 ms 来自更早运行；本轮以相同测量脚本重新取得的 1052 ms 为基线，避免把环境波动算作收益。没有固定实例负载，优化后测量与专用库回归有时间重叠。图像很小且高度可压缩，样本仅 30 次，不能泛化到大图、音频、高并发或持续负载 SLA。

## 正确性与证据

完整回归使用 `--runxfail`：190 passed、45 条既有弃用警告、65.97 秒、退出码 0。新增测试检查读取超时不会覆盖对象、复用无冗余 HEAD、校验读取确实并行且不超过 4 个 worker。原有损坏、删除、音频、拒绝回执契约均通过。

两轮真实云端均通过丢响应重放、提交前失败后的回滚和重试、21 张业务表恢复、4 个资源 SHA-256 核对及清理验证。
